## Canonical input proposed to A

| Column | Spark type | Meaning |
|---|---|---|
| station_id | string | Non-empty station key |
| event_time | timestamp | Proposed five-minute interval endpoint |
| rainfall_mm | decimal(10,3) | A's canonical interval rainfall; null means unknown |
| quality_ok | boolean | Only true marks a valid observation |
| available_at | timestamp, nullable | Conservative final-version publication proxy |
| available_at_basis | string | History requires update_timestamps; slot_only is unknown |

The label builder requires the first four columns and ignores other columns.
Unique `(station_id,event_time)` keys and exact five-minute endpoints are
preconditions; violations raise an error. A owns timestamp normalization,
deduplication, quality flags and station metadata. C does not choose a winning
duplicate. Missing grid rows are allowed: their future windows become unavailable.
Synthetic timestamps include +08:00; Spark session timezone is Asia/Singapore.

## Outcome and interface

Assuming interval-end timestamps, `R30(s,t) = sum(r(s,t+5k minutes), k=1..6)`.
The current observation is excluded. `label = double(R30 > threshold_mm)`;
equality means zero. No rounding/tolerance changes the strict comparison.
Labels use decimal summation at A's canonical 0.001 mm precision. Strict threshold
comparison is performed in integer 0.001-mm units against floor(q*1000), including
thresholds immediately below/above an exact decimal boundary. Synthetic numeric
inputs must also respect this canonical precision; never quantize to 0.2 mm.

`future_slots` counts unique present future endpoints; `future_count` counts
valid readings (quality true, finite, non-negative). Both must equal six for a
valid target. Otherwise `future_30m_mm` is null, `label_available=false`, with
`missing_future_slot` or `invalid_reading` (missing takes precedence).
Each input timestamp provides one prediction anchor; this module does not invent
anchors for missing rows. Report that evaluation is conditional on observed origins.

`src.task2.predict.predict(station_id, prediction_time, threshold_mm)` (with Spark
session as its first implementation argument) returns an exceedance
probability in [0,1], model version, feature availability and extrapolation status.
The CLI exposes the three requested positional inputs. Threshold accepts a finite
non-negative real number. History is retrieved internally; absent usable history
uses the calibrated M1 model. Unknown stations use the indexer's keep category;
q>10 mm is flagged as extrapolation. Model artifacts are generated by the run CLI.

## Temporal protocol

| Split | SGT half-open interval |
|---|---|
| train | [2017-01-01, 2023-01-01) |
| validation | [2023-01-01, 2023-10-01) |
| calibration | [2023-10-01, 2024-01-01) |
| test | [2024-01-01, 2025-01-01) |

Both anchor and target endpoint must be inside one interval. Thus t+30 at the
next split's midnight is excluded. Crossing anchors remain with null split for
auditing; their expanded label is null. Only rows with non-null split and label
may train/evaluate. Generate target truth with cross-file context before split
assignment, then expand thresholds. All threshold copies keep the same split.
History before a split boundary may be read as context; all fitted preprocessing
statistics come only from training data. No randomSplit for main evaluation.

Candidate thresholds: 0, 0.2, 1, 2, 5, 10 mm; held-out candidates: 0.5, 3 mm.
These choices are fixed in `configs/c_model.json` before evaluation.
Training sampling, if necessary, uses label-independent deterministic hashes of
base station/time keys. Natural-distribution evaluation is preferred.

## Availability and leakage

Outcome observations may arrive after prediction time; historical features may
not. `available_at` is not needed to establish target truth. Unknown publication
time must not imply immediately available. Future counts, target values, future
quality and split labels are forbidden model features. Preserve historical
versions where possible; a final corrected value cannot be used before its
publication. The implemented feature builder uses A's conservative availability
proxy; archived data do not establish a perfect historical real-time backtest.
