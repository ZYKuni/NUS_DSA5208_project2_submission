## 发现的问题（需要 C 说明或修改）

1. **超出历史数据范围时静默回退**（`src/task2/predict.py:42-44`、`50-55`）。2025-06-01 的请求返回了 M1 概率，只有 `calendar_fallback=true`，与"站点暂时没数据"无法区分。建议增加 `history_end` 或 `outside_history_range` 字段，或对晚于历史数据末尾的时刻给出警告。
2. **非整五分钟时间直接报错，不取整**（`predict.py:30-31`）。这与 `model_protocol.md` 的说明一致，但用户输入 20:52:30 时得到的是异常。建议在 README 或 CLI 帮助中写明，或提供显式的 `--floor` 选项，向下取整到最近一个已结束的五分钟时隙。
3. **阈值单调性**：S50 2024-04-03 13:20，q 从 0.5 到 1 概率上升 0.22175606832484274。这与 C 在 `results_discussion.md:75` 报告的已知问题一致（测试集 104/222,586 对相邻阈值违反单调性）。报告中应保留这一限制说明。
4. **q>10 时概率不随 q 变化，并可能为精确的 0**。q=10、20、50 三点概率相同（S50 均为 0.233463，S24 均为 0.1375）。S06 在 q≥10 时校准概率为 **0.0**：保序回归输出的下端是 0，对一个概率预测来说过于绝对。`threshold_extrapolation` 只在 q>10 时为 true。建议在文档中说明 q>10 的结果不可信，或对校准输出做裁剪，比如限制在 [1e-6, 1-1e-6]。
5. **不带时区的时间一律按 SGT 解释**（`predict.py:27-28`）。行为正确并已写入文档，但若调用方传入不带时区的 UTC 时间，会静默得到错误时刻的预测（见 f 表）。建议在 CLI 帮助中强调这一点。

另有一条 A 侧的注意事项，与 C 的代码无关：把交接包解压到仓库根目录后，直接运行 `python -m pytest` 会同时收集 `c_handoff_v1/tests`，导致 "import file mismatch" 收集错误。应运行 `pytest tests`，或把交接包解压到仓库之外。

## 结论

- C 交付的模型在 A 的环境中可以独立加载；用 A 复现的清洗数据，推理结果与 C 记录的结果**逐位一致**（a、b 两项差值均为 0.0）。
- 可用时间规则按设计执行：未发布的观测（包括一次约 25 小时的批量补发）没有被使用。
- 没有发现会改变已冻结测试结果的缺陷。上面 5 条属于接口健壮性和文档问题，可以在不重新训练、不重新打开测试集的前提下修改。
